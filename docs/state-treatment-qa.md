# SURA State-Treatment Visual QA

## Scope

The responsive visual QA pass reviewed public discovery, connected shop, protected checkout, AI Studio, company studio, and Personal Edit Studio on desktop (1280 × 720) and mobile (390 × 844). Component-level browser tests separately exercise loading, recovery, and empty data paths that are not visible in a populated preview.

| Surface | State evidence | Primary action remains available |
| --- | --- | --- |
| Connected shop | Honest empty catalog card; no fabricated stock | Category filters and AI-direction route remain available |
| Company studio | Honest empty company state | “Create company” remains visible on desktop and mobile |
| Checkout | Separate service and private-record state treatment | Service-order actions remain independent of record recovery |
| AI Studio | Consent and private-plan boundary hierarchy | Form direction controls remain visible beneath the framing copy |
| Personal Edit Studio | Private daily cue with manual interaction language | No autoplay; manual controls and saved-edit workflows remain available below the hero cue |

## Accessibility and Motion

The mobile captures retain readable editorial headings, non-overlapping controls, visible menu access, and clear section boundaries. The manual Personal Edit rail has automated reduced-motion coverage; non-essential rail transitions are disabled by the existing reduced-motion CSS condition. Empty and recovery components preserve their linked action rather than replacing the whole route with a dead end.

## Limits

Authenticated live company-owner data was not seeded for this visual review. Company-detail loading, error, empty, delivery-settings, and settlement journeys are covered with browser-like component tests; no customer, inventory, order, review, or payment data was fabricated to capture screenshots.
